# Languages and right-to-left

Right-to-left after 40 screens is a project; from the start it's free.

## String keys (apps in more than one language)

Apps that ship in more than one language (customer apps in English and Arabic) follow this section. An app in a
single language (an internal tool in English) may write its text in the code; the rest of this file still applies.

- Each platform has its own catalog (Android `strings.xml`, iOS String Catalog, web/desktop JSON). What they share is
  the **list of keys**.
- Keys are `dot.case`, by screen or area: `auth.signIn.button`. Never the English text as the key.
- A new visible string = its key on every client that shows that screen, in the same change.
- **No literal user-facing text in a view**, not even "for now".
- A missing translation falls back to the base language and warns in debug. Never show the raw key to a user.

## Never glue translated pieces together (translated apps)

Word order changes between languages. Every value goes in a placeholder inside one string:

```
✓  auth.signedInAs = "Signed in as %1$s since %2$s"
✗  localized("signed.in.as") + " " + userName
```

- Plurals go through the platform's plural system (Android `plurals`, iOS catalog variations, ICU on web). Never
  `"$count item(s)"`: Arabic has six plural forms.

## Right-to-left

**start/end, never left/right.**

- Android: `supportsRtl="true"`, `padding(start =, end =)`, `Alignment.Start`. Direction icons mirror.
- iOS: SwiftUI's `leading`/`trailing` mirror by themselves; never hardcode `.left`. Custom direction images use
  `.flipsForRightToLeftLayoutDirection(true)`.
- Web and Electron: `dir` on the root element, and CSS logical properties only (`margin-inline-start`). No
  `margin-left`, no `text-align: left`.
- Mirror the layout, not the content: phone numbers, times, code and Latin brand names keep their direction.
- Text grows in other languages: no fixed-width buttons, no labels that can't wrap.

## Numbers, dates and money

- Format with the platform's locale-aware formatter, never string interpolation.
- Decide once per app whether Arabic shows Western (42) or Eastern Arabic (٤٢) digits, and apply it on every client.
- Money travels as integer minor units + currency code and is formatted on the client.
- Timestamps arrive in UTC and are shown in the user's time zone.

## Error messages

Client error text comes from the API error `code`, never from its `message`. In a translated app, a new code = a new
key and its translations on every client. Unknown code → a generic message.

## Testing

- Apps that ship a right-to-left language: a forced right-to-left pass on every new screen, before the pull request.
- Maestro flows select by test id, so the same flows run with the device in Arabic.
- Translated apps: one test that fails when a shipped language is missing a key.
